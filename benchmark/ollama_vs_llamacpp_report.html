  • H2（克苏鲁陷阱题）：双方均识破“物理学家命名”的错误前提，但所报小说名均不确切。
  • R1（无解数学陷阱）：llama.cpp 胜——368s 推导出“三条件无整数解”的正确结论；Ollama 195.8s 返回空白（关思考档下难题静默失败，前端已有空响应自动重试兜底）。
  • 医学卷：Ollama 抽查（TCA 酶学 / STEMI 再灌注 / DKA 补液 / NOAC 换药）全部准确，X1/X2 边界题拒答得当，能力边界规范行为与基线一致。

  • 翻译卷：译文质量持平；Ollama 明显啰嗦（字数约束遵守差），耗时为基线 5 倍左右。

多模态与缓存专项验证（Ollama MLX）

  • 视觉真实性：✅ 已知图对照测试——图内埋入无法猜到的数值（N=87、p=0.0037）全部逐字读出，曲线终点估值准确，未标注数值明确拒读。无静默幻觉（此前 Ollama MLX vision 曾有图片被忽略+编造的已知问题，issue #17065；图像输入支持于 2026-08-09 合入 runner，PR #17600）。
  • 文本 prompt 缓存：✅ 30K 字长文首问 289.3s → 复问 5.2s，55.7x。
  • 图片前缀缓存：❌ 同图同问两次 TTFT 12.7s / 14.6s，图片每次重新预填充——连续追问同一张图的场景有约 12s 额外开销。
  • 流式：✅ OpenAI 兼容端点 delta.content 正常；thinking 走原生 /api/chat 的 message.thinking 字段（需 think:true）。
  • 速度画像：预填充 ~70–90 tok/s（基线 ~50），解码 ~9.8 tok/s（与基线持平）。官方 MLX 性能数据（1851 tok/s prefill）为 M5 Max 量级，M1 Pro 上带宽（200GB/s）是物理瓶颈。

结论

1. 质量：NVFP4 MLX 与 GGUF Q4 同水平，长尾事实题略好，无量化质量损失；多模态视觉通路真实可用。

2. 速度画像分化：短任务 llama.cpp 快；长思考任务（文献解读 / PPT 等本项目主力场景）Ollama 快约 2x，切换反而受益。

3. 遗留缺口：图片前缀缓存不生效、关思考档偶发空响应（前端已兜底）。适合“文本走 Ollama、多模态追问走 llama.cpp”的双后端策略。
